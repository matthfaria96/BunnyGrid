# BunnyGrid

**English** · [Português](README.pt-BR.md)

A native database client for macOS, built in Swift and SwiftUI.
It connects to **SQLite, PostgreSQL, MySQL, MariaDB, SQL Server (and Azure SQL), MongoDB and Redis**. It shows the object tree, opens tables in a paginated grid and runs SQL in an editor with syntax highlighting.

References:
- **Beekeeper Studio**: architecture (driver contract, connection → tree → tabs flow). Used only as a reference; no code was copied (see [Credits and licenses](#credits-and-licenses)).
- **Navicat Premium**: feature map in `../Clones/Navicat Premium/SPEC.md` (public bundle metadata only). It sets the roadmap in [docs/ROADMAP.md](docs/ROADMAP.md).

## Requirements

- macOS 14 or later
- Xcode 16 or later (the project was made with Xcode 27 and Swift 6.4)

If `xcode-select -p` points to the Command Line Tools, use Xcode just for this session:

```sh
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
```

## Build and run

```sh
swift build                    # builds
swift test                     # core tests (Swift Testing)
scripts/bundle.sh              # builds build/BunnyGrid.app (release); "debug" to debug
open build/BunnyGrid.app
```

You can also open the package in Xcode (`open Package.swift`) and run the `BunnyGrid` scheme.

Distribution build (universal, Hardened Runtime, DMG, notarization and Sparkle): `scripts/release.sh [--notarize]`. Step by step in [docs/DISTRIBUTION.md](docs/DISTRIBUTION.md).

### Development options

```sh
# Isolates saved connections in a temporary folder, opens the sample database and opens a table and a query right away
BUNNYGRID_DATA_DIR=/tmp/bg build/BunnyGrid.app/Contents/MacOS/BunnyGrid \
  Resources/Samples/demo.sqlite --open-table customers --query "SELECT * FROM orders LIMIT 10"
```

With `--query`, `--explain` opens the query plan instead of the result, and in the debug build `--demo-result-edits` creates pending edits in the result, `--result-form` opens the Form View and `--result-profiling` the result's Data Profiling. In the debug build: `--demo-edits` (with `--open-table`) creates sample pending changes, `--focus-cell` focuses a cell, `--show-objects` opens the Objects tab with the Tables folder selected, `--design TABLE` opens Design Table (with `--design-section "Foreign Keys"` or another tab already selected and `--demo-fk` for a pending changed key), `--new-table` opens New Table, `--connect-first` opens the first saved connection, `--begin-transaction` and `--generate` (with `--open-table`) open transaction mode and Data Generation. With `--open-table`, `--export-wizard`, `--import-wizard csv|json|excel|sql [FILE]` and `--execute-sql FILE [--run-script]` open the Export Wizard, the Import Wizard and Execute SQL File (`-export.format sql|xlsx|json|csv` picks the format).
Modes (debug build): `--onboarding` shows the welcome sheet even after it was answered and `--first-launch` decides as a run without arguments would (runs with a file or `--` flags don't cover the window with the sheet); `-interfaceMode simple|advanced` and `-appearance light|dark|system` pick the mode and appearance for that run only.
Also with `--open-table`: `--value-editor [COLUMN] [--row N]` opens the value editor over the cell, `--cell-editor [COLUMN]` opens the Cell Editor panel and `--demo-duplicate` duplicates the first two rows.

Performance measurements: `--bench SCENARIO` (in the debug build, or in release with `swift build -c release -Xswiftc -DBUNNYGRID_BENCH`) runs scripted actions and writes the timings to `BUNNYGRID_PERF_LOG` (one line per measurement: name, ms, detail), then quits the app. Scenarios: `launch`, `connect`, `expand` and `objects` (a database with thousands of tables), `open-table`, `scroll` and `resize` (the `events` table, or `--bench-table NAME`), `tabs`, `typing` and `autocomplete` (with `--bench-script FILE.sql`), `query100k` (`--bench-rows N`) and `er`; `scroll --bench-horizontal` measures only horizontal scrolling, with the grid already at rest, and `scroll`/`resize` also record `grid.blankCells` (visible cells without a view, should be 0). To attach a profiler (`sample`) mid-measurement: `scroll --bench-cycles N` repeats the passes and `tabs --bench-hot --bench-hot-count N` does N tab switches before measuring. The intervals also show up in Instruments (Points of Interest, `PerfTrace`). `BUNNYGRID_BENCH=1 swift test` runs the syntax highlighting benchmark.

### Interface tests (scripted scenarios)

```sh
scripts/ui-test.sh                      # builds the debug app and runs every scenario
scripts/ui-test.sh grid bi --no-build   # only these, without rebuilding
```

`--ui-script FILE.json` (debug build only) runs a scenario **inside the app**: the events (click, double click, right click, drag, keys, scroll wheel, pinch) are created with `NSEvent` and delivered to BunnyGrid's own windows, so the real pointer doesn't move and nothing reaches other apps, even with the app in the background. Targets are found through the accessibility tree (`.accessibilityIdentifier`, label, role) or by the AppKit view class with an anchor (`{"view": "QueryBuilderCanvasView", "anchor": "column:orders.status"}`, `GridTableView` with `cell:ROW,COLUMN` / `header:NAME`, `ERCanvasView` with `table:NAME`). System drag and drop (`.draggable` / `.onDrag`) is delivered straight to the target with a private pasteboard (`dragDrop`). Steps wait for and check the model's state (`{"probe": "tab.query.joins.count"}`, `sql:FILE|SELECT …`, `file:PATH`, `pasteboard`), save screenshots of the window itself and write a `results.json`.

For each scenario, `scripts/ui-test.sh` uses a new folder in `$UI_TEST_OUT` (default `$TMPDIR/bunnygrid-ui-test`) with a copy of `Resources/Samples/demo.sqlite` (`{{DB}}`), `demo2.sqlite`, `empty.sqlite`, its own `BUNNYGRID_DATA_DIR`, an in-memory Keychain (`BUNNYGRID_MEMORY_KEYCHAIN=1`), a copy of the app with another bundle id (separate preferences, wiped before each scenario), open/save panels answered by the scenario (`{"op": "panel", "path": "$RUN/out"}`), a private clipboard, no notifications and no real LaunchAgents. The AI points to a local server (`scripts/ui-scenarios/mock-ai.py`, which imitates the SSE of the Messages API and the Responses API); nothing goes to the internet. Scenarios with `"requires": ["postgres" | "mysql" | "mongo" | "redis"]` use disposable servers on ports 55432 / 53306 / 57017 / 56379 (`UI_TEST_PG_PORT` etc.) and are skipped if those aren't up; `"fixture": "servers"` writes `scripts/ui-scenarios/fixtures/servers/connections.json` and the passwords in memory.

Output: `ok`, `FAIL name: step …` (with a `fail-NN.png` screenshot and the accessibility tree `fail-NN-tree.txt`), `xfail` for scenarios marked `"knownIssue"` (a known bug still open) and `XPASS` when one of those passes. Operations: `wait`, `waitFor`, `assert`, `remember` (and `$name` afterwards), `click`, `doubleClick`, `rightClick` (with `"menu": ["Copy As", "CSV"]`), `hover`, `drag` (`"by": [dx, dy]` or `"to"`, `"release": false` + `release`), `dragDrop`, `key`, `type` (`"replace": true`), `scroll`, `magnify`, `menu`, `menuBar`, `panel`, `screenshot`, `dump` / `dumpViews` / `menuDump` (for writing scenarios), `action` (setup shortcuts: `openTable`, `openQuery`, `runQuery`, `closeTab`, `selectTab`, …), `repeat` (`"times": N, "steps": […]`, with `$i`; `"logEvery"` records memory), `hangs` (`"mode": "start"` / `"report"` with `"maxMs"`: main-thread stretches over the limit, through the bench monitor), `moveFile` (inside the run folder, to simulate a SQLite database that disappears) and `selfTest`; the `memoryMB` probe gives the process's physical memory. The `interfaceMode`, `onboarding` (sheet open) and `onboardingDone` probes follow the modes; the `interface-mode*` scenarios cover the welcome sheet (keyboard and click), the avatar's Theme menu, View › Interface Mode, Settings in Simple, the hidden shortcuts, the Advanced tabs' badge and the existing user (`existing-user` fixture). `scripts/soak.sh [scenario or .json]` runs the long `soak` scenario and passes `leaks`, `heap` (count of live tabs, drivers and grids) and `footprint` on the still-open app; `SOAK_STACKS=1` turns on `MallocStackLogging` (stacks in `leaks`) and `SOAK_KEEP=1` leaves the app open for `leaks --traceTree`. `BUNNYGRID_UI_TRACE=1` logs each delivered event and the view under it.

### PostgreSQL integration tests

With a reachable PostgreSQL (e.g. `brew install postgresql@17 && brew services start postgresql@17`):

```sh
BUNNYGRID_PG_PORT=5432 BUNNYGRID_PG_USER=$USER BUNNYGRID_PG_PASSWORD= BUNNYGRID_PG_DATABASE=postgres swift test
```

Without `BUNNYGRID_PG_PORT` these tests are skipped. Each test creates and drops its own schema.

A disposable server, without touching the system's PostgreSQL (the password is required over TCP, for the wrong-password test):

```sh
initdb -D /tmp/bg-pg -U bunny --auth-local=trust --auth-host=scram-sha-256 --pwprompt
pg_ctl -D /tmp/bg-pg -o "-p 54329 -k ''" -l /tmp/bg-pg.log start
createdb -h localhost -p 54329 -U bunny bunnytest
BUNNYGRID_PG_PORT=54329 BUNNYGRID_PG_USER=bunny BUNNYGRID_PG_PASSWORD=… BUNNYGRID_PG_DATABASE=bunnytest swift test --filter Postgres
pg_ctl -D /tmp/bg-pg stop
```

### MySQL / MariaDB integration tests

```sh
BUNNYGRID_MYSQL_PORT=3306 BUNNYGRID_MYSQL_USER=root BUNNYGRID_MYSQL_PASSWORD=… swift test --filter MySQL
# MariaDB: add BUNNYGRID_MYSQL_KIND=mariadb
```

The user needs CREATE/DROP DATABASE and CREATE USER: each test creates and drops its own database. Without `BUNNYGRID_MYSQL_PORT` these tests are skipped.

A disposable MySQL from Homebrew (`brew install mysql`), without touching the system's `my.cnf` or data (`--no-defaults`; data, socket, pid, log and certificates live in one folder):

```sh
scripts/test-servers/mysql.sh start /tmp/bg-mysql   # initializes the first time, port 33071 (BUNNYGRID_MYSQL_PORT changes it)
eval "$(scripts/test-servers/mysql.sh env /tmp/bg-mysql)"
swift test --filter MySQL
scripts/test-servers/mysql.sh stop /tmp/bg-mysql
```

The script creates a CA plus server and client certificates, starts the server with SSL (without `require_secure_transport`, to test with and without SSL) and the users `bunny` / `bunnypass`, `certuser` (`REQUIRE X509`) and `nopass` (no password, handy for opening the app without the Keychain). `env` also exports `BUNNYGRID_MYSQL_SSL_CA`, `_SSL_CERT`, `_SSL_KEY`, `_SSL_USER` and `BUNNYGRID_MYSQL_SOCKET`; if the socket path goes over the 104-byte limit, it lives behind a short link in `$TMPDIR`. For the tunnel case, add `BUNNYGRID_SSH_PORT`, `_USER` and `_KEYS` (a user `sshd -f <config>` with the `user_ecdsa` key works).

MariaDB through Docker (colima):

```sh
docker run -d --name bg-mariadb -p 127.0.0.1:33081:3306 -e MARIADB_ROOT_PASSWORD=bunnypass mariadb:11
BUNNYGRID_MYSQL_KIND=mariadb BUNNYGRID_MYSQL_PORT=33081 BUNNYGRID_MYSQL_USER=root BUNNYGRID_MYSQL_PASSWORD=bunnypass swift test --filter MySQL
docker rm -f bg-mariadb
```

The SSL, socket and SSH tunnel tests (`ConnectivityIntegrationTests.swift`) use other variables: `BUNNYGRID_TLS_PG_PORT`, `BUNNYGRID_TLS_PG_USER` and `BUNNYGRID_TLS_PG_CERTS` (PostgreSQL with `ssl = on` and its own CA), `BUNNYGRID_PG_SOCKET_DIR`, and `BUNNYGRID_SSH_PORT`, `BUNNYGRID_SSH_USER` and `BUNNYGRID_SSH_KEYS` (an `sshd` with test keys). The comment at the top of the file describes the expected files. With Remote Login off, a user `sshd -D -f <config>` on a high port works.

### SQL Server integration tests

With a reachable SQL Server. On an Apple Silicon Mac, the official container runs under Rosetta (colima or Docker Desktop):

```sh
docker run -d --name bg-mssql --platform linux/amd64 -e ACCEPT_EULA=Y -e MSSQL_SA_PASSWORD='…' -p 14331:1433 mcr.microsoft.com/mssql/server:2022-latest
BUNNYGRID_MSSQL_PORT=14331 BUNNYGRID_MSSQL_PASSWORD='…' swift test --filter SQLServer
docker rm -f bg-mssql
```

`BUNNYGRID_MSSQL_HOST` and `BUNNYGRID_MSSQL_USER` (default `sa`) change the target. The login needs CREATE DATABASE: each test creates and drops its own database. Without `BUNNYGRID_MSSQL_PORT` these tests are skipped; the protocol tests (`TDSProtocolTests`) always run, with sample bytes.

### Redis integration tests

```sh
redis-server --port 63791 --dir /tmp/bg-redis --requirepass secret --daemonize yes
BUNNYGRID_REDIS_PORT=63791 BUNNYGRID_REDIS_PASSWORD=secret swift test --filter Redis
redis-cli -p 63791 -a secret shutdown nosave
```

Cluster and Sentinel (disposable servers: three `redis-server --cluster-enabled yes` + `redis-cli --cluster create … --cluster-yes`, and a `redis-server sentinel.conf --sentinel` with `sentinel monitor mymaster 127.0.0.1 PORT 1`): `BUNNYGRID_REDIS_CLUSTER_PORT=7101 BUNNYGRID_REDIS_SENTINEL_PORT=26391 swift test --filter RedisCluster`.

Uses db 9 and `bunnygrid-test:*` keys. Optional: `BUNNYGRID_REDIS_TLS_PORT` + `BUNNYGRID_REDIS_TLS_CA` (and `_TLS_CERT` / `_TLS_KEY` for a client certificate) for a `redis-server --tls-port`, and `BUNNYGRID_REDIS_SOCKET` for a Unix socket. The socket path must be shorter than 104 characters (macOS limit); a short symbolic link to the socket works. With the RedisJSON module loaded (`--loadmodule …/rejson.so`, included in Homebrew's `redis`) the JSON test runs too.

### MongoDB integration tests

With a reachable `mongod` (e.g. `brew install mongodb-community`). On macOS `--fork` isn't accepted; run it in the background:

```sh
mongod --dbpath /tmp/bg-mongo --port 27071 --bind_ip 127.0.0.1 --logpath /tmp/bg-mongo.log &
BUNNYGRID_MONGO_PORT=27071 swift test --filter Mongo
# With authentication (mongod --auth and a root user in admin; optionally another one created with mechanisms: ["SCRAM-SHA-1"]):
BUNNYGRID_MONGO_PORT=27071 BUNNYGRID_MONGO_USER=bunny BUNNYGRID_MONGO_PASSWORD=… \
  BUNNYGRID_MONGO_SHA1_USER=sha1user BUNNYGRID_MONGO_SHA1_PASSWORD=… swift test --filter Mongo
```

Each test creates and drops its own database. Without `BUNNYGRID_MONGO_PORT` these tests are skipped (the JavaScript shell has its own tests, `--filter JavaScript`). X.509: a new `mongod --tlsMode requireTLS --tlsCertificateKeyFile server.pem --tlsCAFile ca.pem --auth` and `BUNNYGRID_MONGO_X509_PORT`, `_CA`, `_CERT`, `_KEY` (and `_SUBJECT`, default `CN=certuser`); the test creates the admin through the localhost exception and the user in `$external`. In the debug build, with `--connect-first` on a MongoDB connection: `--open-collection NAME [--mongo-view grid|tree|json] [--mongo-filter '{…}'] [--edit-document]` opens the collection viewer and `--mongo-shell 'db.c.find()' [--explain]` opens a shell tab and runs it.

Edit Connection's **Databases** tab: in SQLite, attached files (`ATTACH … AS alias`) on every open connection, next to main; in PostgreSQL, MySQL, SQL Server and MongoDB, which databases show up in the navigator (List Databases reads the server's; the connection's database always shows). Navicat's HTTP tab doesn't exist here: the HTTP tunnel depends on Navicat's tunnel script on the server; use SSH.

In the debug build, `--edit-connection` opens the editor of the first saved connection (`-connectionTab ssl|ssh|advanced|databases` picks the tab) and `--test-connection` runs Test Connection on open.

## Layout

```
Sources/
  BunnyGridCore/          UI-free core (testable)
    Models/               ConnectionConfig, objects, columns, CellValue, QueryResult
    Drivers/              DatabaseDriver protocol + SQLite (libsqlite3), PostgreSQL (PostgresNIO), MySQL/MariaDB (MySQLNIO), SQL Server (own TDS client in `Drivers/TDS`), MongoDB (own client), Redis (RedisDriver)
    Redis/                own RESP2/RESP3 client on SwiftNIO, command-line parser (redis-cli quoting), KeyValueDatabaseDriver, key folder tree, INFO/CLIENT LIST/SLOWLOG
    Mongo/                BSON, OP_MSG over SwiftNIO, SCRAM, mongodb+srv (dnssd), shell parser, DocumentDatabaseDriver, flattening for the grid
    QueryBuilder/         the Query Builder's SELECT model (BuilderQuery), per-dialect SQL generation and a parser for simple SELECTs
    SQL/                  SQLDialect (quoting, paginated SELECT, EXPLAIN), SQLSplitter (splits scripts, statement under the cursor) and QueryPlan (plan tree)
    Network/              SSH tunnel (Citadel), host keys, SSL configuration and the endpoint (TCP, socket or tunnel) used by the drivers
    Transfer/             zip (STORE/DEFLATE) and Excel (.xlsx, write and read), JSON reading for import, running .sql scripts with progress
    Sync/                 Data Transfer between engines, Structure Synchronization (diff + script) and Data Synchronization
    Backup/               .bgbackup format, BackupStore (folder per connection/database/schema), create, restore and extract SQL; SQLite file copy (sqlite3_backup)
    Automation/           BatchJob, JobSchedule (cron, next runs, StartCalendarInterval), JobRunner, launch agents, headless runner
    Storage/              ConnectionStore (JSON in Application Support) and KeychainStore (passwords)
  BunnyGrid/              SwiftUI app
    App/                  BunnyGridApp, AppModel (connections and sessions), Session (tree and tabs)
    Views/                window, sidebar, connection editor, table and query tabs
    Redis/                key browser, per-type viewer, Console, Server Monitor, New Key
    Components/           ResultGridView (NSTableView) and SQLEditorView (NSTextView)
Tests/BunnyGridCoreTests  splitter, dialect and SQLite driver
Resources/Samples         demo.sqlite for manual testing
Resources/AppIcon.icon    the app icon in Icon Composer format (Liquid Glass layers)
scripts/icon              original art and the scripts that generate the icon layers
```

User data:
- connections: `~/Library/Application Support/BunnyGrid/connections.json`
- history: `~/Library/Application Support/BunnyGrid/history.json`
- saved queries and favorites: `~/Library/Application Support/BunnyGrid/queries.json` and `favorites.json`
- AI Assistant conversations: `~/Library/Application Support/BunnyGrid/ai-chats.json`
- API keys: Keychain, services `app.bunnygrid.anthropic` (Claude) and `app.bunnygrid.openai` (ChatGPT)
- profile photo chosen in the app: `profile-photo.png` in the same folder (without it, the macOS account photo is used)
- passwords: Keychain, service `app.bunnygrid.connections` (account `<id>` for the database, `<id>.ssh` for the SSH password or key passphrase, `<id>.ssl-key` for the client certificate key's passphrase)
- backups: `backups/<connection id>/<database>/<schema or _>/<yyyyMMddHHmmss>.bgbackup`
- jobs: `automation/jobs.json`; each run in `automation/runs/<id>.json` (with the log) and a text copy in `automation/logs/`; launchd output in `automation/logs/launchd-<job id>.log`
- schedules: `~/Library/LaunchAgents/app.bunnygrid.job.<id>.plist`, only for jobs with an active saved schedule
- SSH host keys accepted on first use: `~/Library/Application Support/BunnyGrid/ssh-known-hosts.json`

## What already works (v0.7)

- **Practice database** (New Connection › Create a Practice Database, or the button in the empty sidebar): instantly creates a SQLite database with tables, sample data and ready-made queries in the Queries folder, with nothing to install and no user/password (it's a file in `Practice Databases/` in the data folder). Templates: SaaS, Notes, Personal Finance, Tasks, Online Store, Blog and Empty (`PracticeDatabase` in the core, with tests that build each template and run each query).

The window follows Navicat Premium's layout (own icons in SF Symbols; none of Navicat's art is used):

- **Simple and Advanced modes**: on first launch a welcome sheet asks for the mode (Advanced is preselected; ← → choose, Return continues) and the appearance (System / Light / Dark, applied right away). **Advanced** is everything described below. **Simple** keeps a developer's day-to-day: connections (New Connection with only the MySQL, PostgreSQL, SQL Server, SQLite, MariaDB, MongoDB and Redis engines, plus New Connection with URI; editor with General, SSL and SSH), the tree, the Objects tab as a list, tables (edit/insert/delete/apply, Filter & Sort, search, pages, Form View, value editor, Copy As, Import/Export), the SQL editor (Run, Run Current, Explain with the tree, Beautify, autocomplete, history, saved queries, exporting the result), Design Table (Fields, Indexes, Foreign Keys, SQL Preview), New Table, rename/duplicate/empty/delete table, Dump SQL and Execute SQL File, AI Assistant and Ask AI, the Info panel. Gone are BI, Automation, Model, Backup, User, Others, the Function/Trigger/Index buttons (the objects stay in the tree), Data Transfer/Structure Sync/Data Sync, Data Generation, Data Profiling, Data Masking, Table Profile, Query Builder, Begin Transaction, comparing AI answers and Settings' Tabs, Code Completion, Auto Recovery and Advanced pages (saved values still apply). Switch later from the profile photo → **Theme** (Appearance and Interface with a checkmark), in Settings › General or in View › Interface Mode, instantly and without restarting; buttons come and go with a short animation. Nothing is deleted: open tabs of Advanced features stay open and usable in Simple, with an "Advanced" badge, but new ones can't be opened (the ⌘T and ⇧⌘J shortcuts go away). Existing BunnyGrid users (saved connections or preferences) don't see the sheet and stay in Advanced. A single table in the core decides each feature (`Feature` in `BunnyGridCore/Support/InterfaceMode.swift`, with tests); the toolbar, menus, shortcuts, context menus, wizards, editor tabs and Settings pages ask it.
- **Main toolbar**: Connection (types menu), New Query, Table, View, Materialized View, Function, Role, Others, Query, Backup, Automation, Model, BI, About, AI Assistant and account. Object type buttons show that category in the Objects tab. Role is disabled ("coming soon"); BI opens a new or saved workspace; Automation opens the jobs window and Backup shows the Backups folder.
- **Navigation pane**: BunnyGrid Cloud (coming soon) → My Connections → groups (folders) → connections → databases → schemas (PostgreSQL) → Tables / Views / Materialized Views / Functions / Queries / Backups → objects. Opening a node connects or opens the database; in PostgreSQL each database has its own connection. At the bottom: search, locate the open tab's object and collapse all.
- **Tabs**: a fixed "Objects" tab and tabs like `payment @dvdrental.public (PostgreSQL)`. The window title follows Navicat (`… - Table - BunnyGrid`).
- **Objects tab**: Open / Design / New / Delete, Import / Export Wizard and search; lists the objects of the selected folder or the connection's databases.
- **Table tab**
  - toolbar: Table Profile, Begin Transaction, **Cell Editor**, **Filter & Sort**, **Columns** (show/hide), **History** (SQL run by the tab), **Fill with AI**, Data Profiling, Import, **Export**, Data Generation, Data Masking, Create BI Workspace (items without highlight are coming soon)
  - a grid with a two-line header (name and type: `# int4`, `numeric(5,2)`, `timestamp(6)`), an indicator column, the focused cell, `(Null)`, pending edits, deletes and inserts with Apply/Discard in a transaction
  - footer: + − ✓ ✗ ↻ ■, first/previous/page/next/last, records per page (1000 by default), search in the grid, Grid View / **Form View** (long or multi-line text, JSON and blobs get a multi-line field and the button that opens the value editor)
- **Query tab**: editor with highlighting, autocomplete, history and export. **⌘S saves the query** in the database's Queries folder (with a name); ⌘S again updates it.
  - **Run** (⌘↩) runs the selection or the whole editor; the Run menu and the editor's context menu have **Run Selected**, **Run Current Statement** (⌘⇧↩, the statement under the cursor) and **Run All**. **Beautify SQL** (⌘⇧B) formats locally.
  - **Explain** shows the plan of the selected statement or the one under the cursor without running it (`EXPLAIN QUERY PLAN` in SQLite, `EXPLAIN (FORMAT JSON)` in PostgreSQL, `EXPLAIN FORMAT=JSON` in MySQL/MariaDB) in an **Explain** tab with the plan tree (cost, rows, conditions) and the raw result in Data.
  - **Stop** (⌘.) cancels on the server: `pg_cancel_backend` and `KILL QUERY` through a second connection, `sqlite3_interrupt` in SQLite.
  - Each query tab has **its own connection** (opened on the first run, with the Initial Queries, closed with the tab): a transaction open in the editor doesn't mix with edits applied in table tabs. In-memory SQLite stays on the database's connection.
  - Results read at most the limit in Options › Records (1000 by default); the footer shows **Load More** and **Fetch All** for read queries.
  - **Edit Result**: a single-table `SELECT` (no JOIN, GROUP BY, DISTINCT, UNION, CTE or subquery in FROM; `ResultEditTarget`) whose primary key is in the result can be edited in the grid itself, with the same pipeline as the table tab (+ − ✓ ✗ in the footer, values as typed parameters, value editor, Duplicate, Set to DEFAULT); expressions and renamed columns stay read only. After Apply the statement runs again. Otherwise the result is read only and the Edit Result button says why. The result's **Data Profiling** computes the statistics on the rows read, in memory; the result's **Form View** uses the same form as the table tab.
- **Design Table / New Table**: a grid of fields (name, type with suggestions from the database, Not Null, key, Default), Fields / Indexes / Foreign Keys / Uniques / Triggers / Options / SQL Preview tabs. Saving generates `CREATE TABLE` or `ALTER TABLE` (drop, rename, change type/null/default, add a field, rename the table) and runs in a transaction in PostgreSQL and SQLite; in SQLite, what `ALTER TABLE` can't do becomes a table rebuild. What the designer doesn't support (e.g. changing the primary key in PostgreSQL/MySQL) is flagged before saving. In the Fields tab, each field's **Comment** and **Collation** in PostgreSQL (`COMMENT ON COLUMN`, `ALTER COLUMN … TYPE … COLLATE`) and MySQL/MariaDB (in `MODIFY COLUMN`); in Options, the **Auto Increment** value (the next id: `sqlite_sequence` in SQLite with AUTOINCREMENT, `AUTO_INCREMENT = n` in MySQL); in SQLite's Uniques tab, each unique's **ON CONFLICT** (written as `UNIQUE (…) ON CONFLICT …` in `CREATE TABLE` or in the rebuild, which now also keeps the AUTOINCREMENT counter).
- **Navicat for macOS look**: a window without a title bar, with the title next to the window buttons, a toolbar of illustrated icons (gradient tiles with badges), a **View** control and an avatar; a **translucent navigation pane** (blurring what's behind the window, like Finder); a right panel with **ⓘ Info** (connection, database or table card) and **AI** tabs; an Objects tab with an icon bar, list/grid mode and Rows, Data Length, Engine, Created Date and Modified Date columns; a centered summary in the status bar; a connection context menu (star, color, groups, run SQL file…).
